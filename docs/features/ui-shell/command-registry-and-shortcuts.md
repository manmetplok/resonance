# Command registry and keyboard shortcuts

> Verified against master @ `8eac71b3` on 2026-10-07.
> Spec history: `docs/history/specs/command-palette.md` (P0, P1, P3, P5).

Every user action that takes no free-form argument is a command in one
registry. Each command has a name, a category, search keywords, a glyph, a
typing gate, a repeat rule, a scope and a default chord. The global key
handler, the command palette, tooltips, menu hints and the Performance
footer all read from this registry, so no view or reducer matches a key
literal. A user can press a shortcut, find the same command in the palette
([command-palette.md](command-palette.md)), or rebind it in Settings ›
Keyboard ([keymap-editor.md](keymap-editor.md)).

## Behaviour

**Commands.** `CommandId` has 102 variants in six categories: Transport,
Editing, View & Navigation, Compose & Vocal, Mixer and Project.
`CommandId::ALL` is generated by the same macro as the enum, so the palette
order always includes every variant. `CommandId::key()` returns the variant
name (for example `"TransportTogglePlay"`), which is the stable id used in
`settings.json`. Renaming a variant therefore changes the file format.

**Availability.** `availability(&Resonance)` returns `Yes` or
`No(reason)`. Examples of reasons: "Arm a track to record", "Open a MIDI
clip first", "Select a section with room after it", "A project load or save
is in progress". A shortcut for an unavailable command does nothing. The
palette shows the command dimmed with its reason.

**Building the message.** `to_message(&Resonance)` resolves the current
selection into an id-carrying message, such as `SplitClipAt { clip_id, … }`
or `SetLoopRange { …, enabled: Some(true) }`. Commands that create
something (Split Clip, Add Drum Track) go through `build(&mut Resonance)`,
which allocates the new id the same way the control API does. Commands
that act on several tracks (`ToggleMuteSelected`, `ToggleSoloSelected`,
`ToggleArmSelected`, `FreezeSelectedTracks`) are single reducer messages,
so one key press makes one undo entry.

**Global dispatch order** (`update/shortcuts.rs::handle_key`). Every key
press arrives as `UiMessage::ShortcutKey { chord, repeat, captured }` from
`iced::event::listen_with`, which also sees keys a widget captured. The
reducer then works through these steps:

1. A Keyboard-panel rebind that is waiting for a chord takes the key.
2. The open palette takes Esc, ↑/↓ and an uncaptured ↵.
3. Esc drops an armed preset drag. The preset browser takes Esc, ↑/↓ and ↵.
4. Esc cancels an inline rename, then closes one layer of the mixer
   inspector's CHAIN transient state (drag, preset prompt, replace mode,
   popover).
5. Any other key a widget captured (a focused text field, or a canvas that
   owns the keys) is dropped.
6. Esc closes the topmost modal overlay. If none is open, Esc closes the
   generic plugin window, then disarms an armed MIDI Learn.
7. While a modal overlay is open, only ⌘/Ctrl chords go further.
8. The chord is looked up in `r.ui.keymap` in `Scope::Global`.
9. A key repeat is dropped unless `repeat()` is true. That is the case only
   for the four nudges and the two zoom pairs.
10. `run_shortcut` checks availability, then the typing gate, then
    dispatches through `execute`. That re-checks availability, builds the
    message and records the command as recent if it got past the
    startup, bounce and freeze gates.

**Typing gate.** A chord without ⌘/Ctrl is always typing-gated, whatever
`gate()` says, so a preset or a rebinding cannot put an ungated letter on a
command. Undo and Redo are gated too, because iced has no text undo. The
gate is a focus probe (`focus::any_text_input_focused`) that answers with
`UiMessage::ShortcutProbed { command, editing }`. Tests replace it with
`TypingProbe::Assume`.

**Platform chords.** `KeyChord::from_iced` maps iced's `command()` (⌘ on
macOS, Ctrl elsewhere) to `mods.cmd`. Outside macOS, a chord that includes
Super/Logo binds nothing. `+` is `NamedKey::Plus`, because `+` separates
tokens in the text form. `keycaps(Platform)` and `format_for_platform()`
render `⇧⌘S` on macOS and `Ctrl` `Shift` `S` elsewhere.

**Scopes.** Canvas-local keys are registry entries with a canvas `Scope`:
`Timeline` (Delete Selection), `MidiEditor` (Delete Notes, ⌘A, ⇧⌘A),
`VocalRoll` (Delete Note, S / + for slur) and `ExpandedEditor` (+/− zoom,
Esc collapse). The canvases match chords through `keymap.matches(id,
chord)`, only while they own the keys (`KeyFocus::owns_keys`). Inside its
scope a canvas chord may shadow a global one. Every canvas ignores keys
while a modal overlay is open or a rebind is capturing
(`Resonance::canvas_keys_blocked`). Without that check, Backspace typed in
the palette would delete the selected clip.

**Default keymap** (`BindingMap::resonance_default`). This list is a
summary; the code is the full table.

- **Project:** ⌘K and ⇧⌘P palette, ⌘N, ⌘O, ⌘S, ⇧⌘S, ⌘B bounce, ⇧⌘E
  export, ⌘I import MIDI, ⇧⌘I import audio, ⌘, Settings.
- **Editing:** ⌘Z, ⇧⌘Z and ⌘Y (an alternate), ↵ open MIDI clip, ⌘Esc
  close editor, ⌘E split, ⌘D duplicate, Q quantize, ⌘L loop selection.
- **Transport:** Space play/stop (returns to where playback started), ⇧Space
  play/pause, ⌥Space play from loop start, R record, L loop, K metronome.
- **Playhead:** Home/⌘← start, End/⌘→ end, `[` `]` loop edges, I/O set the
  loop edge, ⇧L loop the section at the playhead, ←/→ nudge one bar, ⌥←/⌥→
  nudge one beat, `,`/`.` previous/next marker, ⇧,/⇧. previous/next section,
  ⇧M add marker, ⌘J go to bar.
- **Views:** ⌘1/⌘2/⌘3 Arrange/Mixer/Compose, F Performance mode, Esc exit
  it, ⌘=/⌘− zoom, ⌥⌘B browser, ⌥⌘G global tracks.
- **Mixer:** ⌘G group, ⌘F/⇧⌘F freeze selected/all, ⌘T/⇧⌘T audio/instrument
  track, ⌥⌘T add-track menu, M/S/⇧R mute/solo/arm selected, ⌘⌫ delete
  track (asks first).

The transport and playhead behaviour behind these commands (`TogglePlay`,
`SeekTarget`, `SetLoopPoint`, the `update/transport_nav.rs` maths) is
documented with transport in [transport.md](../hardware-io/transport.md).

**Shortcut hints.** `view/shortcut_hint.rs` provides `chord_text`,
`hint_text` ("Save (Ctrl+S)") and `with_hint`, which wraps a widget in a
tooltip. They are used on the view tabs, the transport buttons, Import,
Settings and the track-menu freeze rows. The Performance footer builds its
"Space play · R record · F fullscreen · Esc exit" hint from the registry.

**Not commands.** Holding B auditions the reference in the Mixer. That
needs both press and release, so it is a separate subscription
(`update.rs::reference_momentary_keys`). Its typing gate is
`UiMessage::RequestShortcut`.

## Where the logic lives

| Concern | Location | Key items |
|---|---|---|
| Registry metadata | `resonance-app/src/commands/mod.rs` | `CommandId`, `CommandCategory`, `KeyGate`, `Scope`, `Available`, `gate`, `repeat`, `scope`, `keywords`, `records_recent` |
| State-aware resolution | `resonance-app/src/commands/resolve.rs` | `availability`, `to_message`, `build`, `selection_range`, `duplicate_target` |
| Chords | `resonance-app/src/commands/chord.rs` | `KeyChord`, `Mods`, `NamedKey`, `ChordKey`, `Platform`, `from_iced`, `parse`, `format_tokens`, `keycaps` |
| Binding table, presets | `resonance-app/src/commands/bindings.rs` | `BindingMap::resonance_default`, `command_for`, `chord_for`, `set_primary`, `KeymapPreset` |
| Global dispatch | `resonance-app/src/update/shortcuts.rs` | `key_event_message`, `handle_key`, `run_shortcut`, `probed`, `execute`, `key_press_command` |
| Subscription | `resonance-app/src/update.rs` | `subscription` (`listen_with` → `ShortcutKey`) |
| Overlay gate | `resonance-app/src/state/overlay.rs` | `Overlay::blocks_keys`, `modal_overlay`, `canvas_keys_blocked` |
| Hints | `resonance-app/src/view/shortcut_hint.rs`, `view/transport.rs`, `view/menus.rs` | `with_hint`, `chord_text` |
| Keycap widgets | `resonance-app/src/theme.rs` | `kbd` glyphs, `keycap`, `keycap_row`, `KeycapTone` |

Invariants a change must keep:

- No chord resolves to two commands in one scope.
- Every bare-key binding is typing-gated.
- Only nudges and zoom repeat.
- A multi-target command is one reducer message, so it makes one undo
  entry.

## Surfaces

- **GUI:** keyboard everywhere; tooltips on the chrome and transport; hints
  in the track menu and the Performance footer.
- **Control API / MCP:** none. Agents have typed tools for each action, and
  the registry is not exposed over the socket.
- **Agent skills:** none.

## Decisions and deviations

- Recommended options were taken for D1 to D7, because the open decisions
  were never answered. Space returns to the play-start position; M and S are
  mute and solo; K is the metronome; ← and → nudge the playhead globally.
- ⌘G stays Group Selection. Global Tracks moved to ⌥⌘G.
- ⌘D (Duplicate Selection) only duplicates a section placement into the
  bars after it. There is no clip-copy primitive
  ([intent](../../intents/timeline/clip-copy-duplicate.md)).
- Select Notes in View (⇧⌘A) works only inside the piano roll. In the
  palette it is listed but dimmed ("Press it in the MIDI editor").
- Add Control Track from the spec shipped as Add Drum Track.
- The spec showed dotted command ids (`transport.toggle_play`). The build
  uses variant names.

## Known gaps

- There is no clip duplication
  ([duplicate-clip-selection](../../intents/timeline/clip-copy-duplicate.md)).
- ⌥ with Delete/Backspace on canvases is not bound. The ⇧ and ⌘ variants
  are.
- `T`, `P`, `U`, `W`, `Y`, `X`, `C`, `V` and the digits are deliberately left
  free for future tools. Tap tempo is not built.
